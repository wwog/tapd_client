# Internationalization (i18n)

The product ships Chinese and English. Messages are addressed by **short
semantic keys**; each catalogue entry carries both languages side by side.

## Key model

```ts
// apps/desktop/src/lib/i18n/catalog/shell.ts
export const shell = {
  "app.nav.projects": ["项目管理", "Project management"],
  "app.projects.empty": ["选择左侧项目开始", "Select a project on the left to start"],
  "app.agent.pending": [
    "{n} 个 Agent 任务待处理",
    ({ n }) => `${n} agent task${Number(n) === 1 ? "" : "s"} pending`,
  ],
} as const satisfies Catalog;
```

- Key = short, dot-namespaced id: lowercase segments, `lowerCamel` after the
  namespace (`common.save`, `bugs.sortAscending`, `agent.status.queued`).
  Aim for ≤ 40 characters; namespaces keep lookup cheap and avoid collisions.
- Value = `[Chinese, English]`. Both languages are written together, so a
  translation cannot go missing in one language.
- Placeholders are named (`{n}`) and identical in both languages; English may
  reorder them. Counts that change the English noun use a function for the
  English side.
- A key is the stable identity: rewording either language does not touch call
  sites. Reuse a `common.*` key when the meaning matches; otherwise name the
  key after its screen and purpose, not its copy.

Frontend:

```tsx
import { t } from "../lib/i18n";

t("common.save")                        // 保存 / Save
t("bugs.sortAscending", { label })      // 按 {label} 升序 / Sort {label} ascending
```

`t()` is typed against the merged catalogue: a wrong key is a compile error.
Module-level constants that render must store the **key** and call `t(key)` at
render time (never call `t()` at module scope — that freezes the startup
language).

Catalogue files:

- `apps/desktop/src/lib/i18n/catalog/{common,shell,settings,bugs,agent,workbench,misc}.ts`
- `apps/companion/src/lib/i18n/catalog/{common,shell,agent,misc}.ts`

Language switches re-render both roots (`main.tsx` subscribes to
`subscribeLocale`); no component needs its own subscription.

## Rust

```rust
use tapd_i18n::{tr, tr_args};

// ("agent.git.noRepo", "Git 仓库尚未初始化", "Git repository is not initialized")
tr("agent.git.noRepo")

// format! needs a literal template, so tr_args substitutes instead.
// `{}` consumes arguments in order; English may use `{0}`/`{1}` to reorder.
tr_args("agent.startup.timeout", &[&secs])
```

- Catalogue: `crates/tapd-i18n/src/catalog/{common,core,mcp,agent,bug,notification,companion,app,misc}.rs`,
  entries are `("key", "中文", "English")`.
- Keys are typed by tests: `cargo test -p tapd-i18n` rejects duplicates,
  malformed keys, keys over 48 characters, empty strings and CJK left in the
  English column.
- Locale is process-wide (`tapd_i18n::set_locale`), set at startup from the UI
  preference (`locale.rs`) and pushed by the webview once resolved.

## What is translated

Translate everything a user can read:

- UI labels, buttons, empty states, tooltips, dialogs, toasts, setup guides.
- Backend strings that reach the UI: command errors, agent lifecycle/status
  messages, runtime descriptions and capabilities, notification titles/bodies,
  MCP tool descriptions and generated prompts, diagnostics text.
- ARIA labels, `title` attributes, native notification text.

Do **not** translate:

- Code comments and `tracing`/`eprintln!` developer logs (diagnostics bundles
  are for support, not the UI). Mark intentionally-Kept Chinese code strings
  with a trailing `// i18n-exempt: <reason>` comment.
- Test fixtures, mock data, HTML fixtures under `fixtures/`.
- Identifiers, enum values, JSON keys, CLI flags, URLs, file names, strings
  that are compared or parsed, command arguments.
- Proper nouns: TAPD, MCP, Agent, CLI, GitHub, runtime names (Claude Code,
  Codex, …), model names.
- TAPD data itself (bug titles, comments, member names) — that is user content.

## English style

- Sentence case for labels and titles ("Sign out", "Bug details", "Open in
  browser"), not Title Case.
- Short: UI labels are verbs/nouns, no filler. Details go into `title` as the
  Chinese copy does.
- ASCII punctuation ( `.` `,` `:` `?` `!` `()`); no full-width punctuation.
  Keep `…` only where the message is a pending action ("Loading…").
- Keep `{placeholders}` exactly; never translate placeholder names.
- Prefer neutral phrasing for counts inside Rust templates ("Files: {0}",
  "Queued tasks: {0}") because `tr_args` has no plural selection.
- Product vocabulary: bug, workspace, project, owner, developer, severity,
  priority, status, agent, runtime, task, approval, merge, worktree, capsule.
- Chinese quotes 「」 become `"…"` or are dropped.

## Verification

- `pnpm i18n:check` — reports missing catalogue keys, Chinese literals not
  passed through `t()`/`tr()`, duplicate/unused keys, and zh/en placeholder or
  punctuation drift.
- `pnpm typecheck` and `cargo test -p tapd-i18n` / `cargo check --workspace`.
- Manual pass: switch Settings → Appearance → 语言 to English and walk the main
  screens (list, detail, agent, settings, capsule, companion).
